# v0.7.1 — One memory across Claude Code, OpenCode and Codex

OpenCode and Codex can now use the same vault, project context and Brain skills as
Claude Code. Each adapter follows its client's native lifecycle; memory stays in
the existing local Markdown vault and search index.

## Highlights

- 🧠 **OpenCode integration:** a global server plugin supplies project context,
  recall and tool guidance. A separate minimal TUI plugin shows memory status;
  command wrappers expose Brain workflows in the client.
- 🛠️ **OpenCode setup, diagnostics and removal:** the installer manages the files
  it owns, detects conflicting installations and preserves unrelated settings.
  Packaged installer assets work without an npm build during setup.
- 🔗 **Codex native hooks:** bootstrap, project/global hybrid recall, pre-action
  guidance and save reminders use the native hook lifecycle. A semi-manual
  quickstart covers MCP registration, hooks and shared skills.
- 📚 **Canonical skills across clients:** bootstrap, recall, save, retrospective
  and autolearn keep the same procedures, with native invocation and path handling
  for each client. Discovery accepts paths pointing to the same physical skill
  directory while still detecting distinct competing copies.
- 📦 **Self-contained package resources:** `init-vault --vault PATH` scaffolds a
  vault; `resources --skills` and `resources --routing` locate installed resources;
  `codex-hooks` renders hook configuration to stdout.

The release candidate passed 1819 Python tests on Windows (9 platform-specific
skips), 139 OpenCode Node tests, package installation checks and native-client
delivery checks. Field use confirmed OpenCode bootstrap, automatic memory
delivery, MCP reads/searches and saving against an existing vault.

## Worth knowing before you upgrade

Close clients using the installation before upgrading. On Windows, a running
MCP server can hold the executable open.

```sh
uv tool upgrade symbiosis-brain
```

- **Claude Code:** refresh installed hooks and skills with
  `symbiosis-brain setup claude-code --repair`, then restart the client.
- **OpenCode:** run `symbiosis-brain setup opencode --vault /path/to/vault`, then
  restart OpenCode. Check the installation with
  `symbiosis-brain doctor opencode`. If a launcher supplies a temporary provider
  configuration, pass `--config-dir /path/to/opencode-config` explicitly to doctor.
- **Codex:** follow the [Codex quickstart](https://github.com/Krill113/symbiosis-brain/blob/v0.7.1/docs/codex-quickstart.md). Automatic
  Codex setup, repair and uninstall are deferred; review and trust the installed
  hook definitions in the native client before use.
- Existing notes and the selected embedding model are preserved. Adding another
  client does not require a new vault or an embedding-model migration.
- Setup refreshes packaged skills. Preserve any local skill customizations before
  repairing or replacing their installation.

## Current boundaries

- OpenCode save checkpoints are reminders, not a hard stop.
- OpenCode Git synchronization is explicitly deferred; its command does not
  pretend that an index refresh synchronizes the vault with a Git remote.
- The existing Claude Code integration remains supported alongside the new
  adapters.

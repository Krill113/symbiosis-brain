# v0.6.0

Memory that can be measured. This release adds a local record of what the memory
actually served, fixes the keyword half of search — which was returning nothing at
all on most real questions — and adds a report that tells you which notes are
working for you and which are dead weight.

## Highlights

- **The keyword half of search was silently answering nothing.** Query tokens were
  joined into an implicit AND, so a natural-language question had to match every
  word to return a row. Measured over 1666 real queries from a month of sessions:
  **the lexical half returned zero rows on 84.5 % of them — now 0.2 %.** Recall
  ranked first on Russian queries went from 0.12 to 0.83 in the same measurement.
- **Every search is recorded locally**, from both MCP tools and hooks: the query,
  the number of hits, which notes came back, and the end-to-end hook latency. Two
  new tables inside `<vault>/.index/brain.db`. Nothing leaves the machine, rows
  rotate after 90 days, and one environment variable turns it off.
- **A new tool, `brain_report`** (and `brain-cli report`, same text). One screen:
  what the memory served this month, which notes were surfaced and read, which
  ones nobody has opened or edited in a long time, and how complete the log is.
- **Notes now say who wrote them** — `written_by:` carries client, version, model
  and date, recording the last write through the product. Existing notes are left
  untouched; an absent line simply means "written before this release".
- **`brain_write` warns about near-duplicates** before it writes. A `[dedup]` line
  names up to two existing candidates with their gists. It never blocks the write.
- **Recall fires on PowerShell commands, not just Bash.** Warnings drawn from past
  mistakes now reach the moment of a risky command on both shells, and routing
  hints are injected into a subagent's prompt — the memory a subagent needs most
  is the memory it never had.
- **The installer tells the truth.** `doctor` now reports the SQLite build (naming
  a version vulnerable to the WAL-Reset race), runs `PRAGMA quick_check` on every
  run, compares installed hooks against the packaged ones and says **STALE** when
  they differ, and names missing MCP permissions instead of counting them.

The suite grew from 765 to 1097 tests.

## Worth knowing before you upgrade

- **Run `symbiosis-brain setup claude-code --repair` once after upgrading.**
  Installing the package does not touch `~/.claude/hooks`, so without it the model
  bridge and hook timing stay on the old code, the widened PreToolUse matcher
  (PowerShell recall) is never installed, and `brain_report` is missing from
  `permissions.allow` — the tool exists but asks for permission on every call.
  `doctor` now flags each of these by name.
- **The first start on an existing vault migrates the database once** to add the
  two log tables. It is quick and needs no action.
- **The retrieval log stores query text** — on the hook path, that is your prompt,
  truncated to 2000 characters — in the local database. Turn it off with
  `SYMBIOSIS_BRAIN_RETRIEVAL_LOG=off` (server and hooks) or
  `"retrieval_log_enabled": false` in `~/.claude/symbiosis-brain-pre-action.json`.
- **The ★ mark in `[recall:]` means something narrower now.** It used to mean "this
  note appeared in both halves of the search"; after the lexical fix that was true
  of 54.9 % of queries and distinguished nothing. It now means top-3 in both halves.
- **`brain_lint` prints a short report by default.** Stylistic findings moved behind
  `brain_lint(verbose=true)`; every counter still appears in the summary line.
- **`--repair` keeps only the three newest `.bak.*` copies** of each file it
  replaces, instead of accumulating one per run forever.

The embedding model is unchanged (`BAAI/bge-small-en-v1.5`): candidates were
benchmarked for this release and none of them won on the available evidence.

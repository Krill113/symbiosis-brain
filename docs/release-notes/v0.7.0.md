# v0.7.0

Hook recall now searches the project you are in, and note dates can be trusted. The
hooks had been searching only global notes in every project; they now find the
session's own scope. A note's age, its closure and its history survive re-syncs, moves
and reindexes. A fresh install gets the dependency versions this release was verified
with. And parallel sessions stop re-polling every MCP server and stop blurring their
own traffic into the retrieval log.

## Highlights

- 🎯 **Recall in hooks searches your project again.** The hooks read the session scope
  from a variable Claude Code never passes to them, so every prompt recall fell back to
  global notes only — 211 of 213 logged prompt-recall events over a week, in every
  project. They now resolve the scope themselves from the project's `CLAUDE.md`
  marker; when nothing resolves they search everything and say so, instead of
  silently narrowing. The status line shows the real scope too.
- 📌 **A fresh install gets the versions it was verified with.** `onnxruntime` was not
  declared at all and arrived with no upper bound; on one machine a fresh install
  picked up a release that hung embedding on a real vault and ran about 7× slower.
  The embedding stack — `onnxruntime`, `fastembed`, `tokenizers`, `numpy` — is now
  bounded to the versions tested together.
- 📅 **Note age is real again.** The staleness warning read a column that every
  re-sync rewrites: on a live vault it fired 0 times out of 1635 notes. It now reads
  the note's own `valid_from` and fires on 53. Notes with no date are counted instead
  of passing as fresh — a new `undated` category in `brain_lint` (282 of 1649 on the
  same vault).
- 🗂️ **A moved note keeps its dates.** A rename used to be a delete plus a fresh
  insert, so a layout migration re-aged 1525 notes into one 28-minute window. Moves —
  through `brain_rename` or made on disk behind the server's back — now keep both
  stamps, and a full reindex no longer restamps the whole vault.
- 🧱 **The scope-first vault layout** — a project's notes, card and archive under one
  `<scope>/` folder — is supported alongside the legacy one, and a fresh vault starts
  in it. Existing vaults are not converted.
- 🧯 **One odd note no longer stops the whole sync.** A single unquoted date in a note's
  frontmatter aborted the sync of the entire vault, with an error that named no file —
  on one `git pull` it left 357 notes unsynced. Dates are now stored as text, and
  whatever still cannot be stored fails that one note, reported by its path.
- 🔒 **Closed notes stop being served as current.** A note with a past `valid_to` no
  longer turns up in injected recall; `brain_search` still finds it, and the duplicate
  check marks it as closed instead of hiding it.
- ✏️ **`brain_patch` edits frontmatter fields** — `gist`, `tags`, `valid_to`, `title`
  and the rest — not only the body. A title change names the notes whose links it
  breaks.
- 🩺 **`doctor` stops printing green over broken states.** On 2026-09-02 it printed
  All OK while the vector index was empty. It now checks compiled action rules, the
  vector index and a reindex lock left behind by a dead process — and says what that
  lock costs and when it clears on its own. A fresh vault with no action rules
  declared is accepted when its compiled result is valid and empty, without hiding
  skipped rules or validation warnings.
- 📡 **Parallel sessions stop re-polling every MCP server.** `claude mcp list` starts
  every configured server to health-check it. After a crash, five sessions restarting
  together produced five full polls in two and a half minutes. The answer is now
  shared per project directory and reused for up to a day, invalidated by the content
  of the configuration it depends on.
- 🏷️ **The retrieval log tells harness messages from human prompts.** On one busy day
  337 of 589 prompt-hook rows were cross-session messages, task notifications or agent
  reports. They are now labelled, and `brain_report` shows the search-agreement share
  with and without them.
- 🧭 **The embedding model is switchable, and candidates are measured fairly** —
  normalised vectors, per-model dimension, per-model query prefixes, the active model
  recorded in the vault's own database. `intfloat/multilingual-e5-small-int8` is
  registered as an opt-in multilingual model.
  The package default remains `BAAI/bge-small-en-v1.5`. To opt in, set
  `SYMBIOSIS_BRAIN_EMBED_MODEL=intfloat/multilingual-e5-small-int8` for the server;
  changing the model rebuilds the vector index at startup. Existing model choices
  are preserved when no change is requested.
- 📊 **The status line reads the fields for the current session.** Context and model
  come from their own payload fields, and runtime effort takes precedence over
  configuration defaults. Missing or all-zero usage is shown as unknown rather than
  a misleading 0%; save thresholds use only fresh, matching context observations.
  A real decrease after compaction and a genuinely rounded 0% remain valid.
- 🛠️ **Install and repair fixes.** `setup claude-code --repair` failed and rolled
  itself back on a non-UTF-8 Windows locale; `brain_lint` raised on every fresh
  install; onboarding saved the user's profile where nothing reads it; and
  `setup --vault` on an existing install reported a new vault while every session
  kept using the old one — it now moves the registration and says what it did.

The suite grew from 1097 to 1345 tests: 1344 passed on Windows, with one symlink
privilege test skipped.

## Worth knowing before you upgrade

- **Close every Claude Code window before `uv tool upgrade`.** On Windows a running
  `symbiosis-brain serve` holds the executable, and the upgrade fails with
  `os error 32`.
- **Then run `symbiosis-brain setup claude-code --repair`.** The hooks and the shipped
  skills changed; installing the package does not touch `~/.claude/hooks` or
  `~/.claude/skills`. Without the repair, recall keeps searching only `global` notes
  and the MCP roster cache is never used.
- **The upgrade may move some dependencies back.** If your install had picked up a
  newer `onnxruntime`, `tokenizers` or `numpy`, the upgrade replaces them with the
  verified versions — on purpose. A workaround such as
  `--with "onnxruntime==1.24.4"` is no longer needed.
- **Notes under a folder named `files` leave the search index.** Such folders now hold
  material, not notes. The first sync after the upgrade removes their index entries
  and vectors; the files themselves stay on disk. To see whether this touches you,
  look for Markdown files inside any folder named `files` in your vault. If some of
  them are real notes, move them out of that folder — they are indexed again at their
  new path.
- **No file in your vault is moved or deleted, and the layout is not converted.** Sync,
  lint and rotation read both the legacy and the scope-first layout. What changes is
  where new project cards go: the skills `--repair` installs create them at
  `<scope>/<scope>.md`, so a vault that keeps the legacy layout will hold new cards in
  the new place and old ones where they were.
- **Session start runs one more synchronous check** — `mcp-roster check`, bounded by
  a 3-second timeout, falling back to the old behaviour on any failure. It adds
  roughly half a second to the start of a session: 0.51–0.65 s for the whole
  command, start of `uv` included, measured on a busy machine.
- **The first start migrates the retrieval log once:** a `query_kind` column is added
  and the existing rows are labelled — on a copy of a 2838-event log this took 50 ms.
  A window still running the old version keeps writing unlabelled rows until it is
  restarted; the daily rotation labels them.
- **`serve` no longer creates a vault at a missing path.** It exits naming the path
  and points at `setup`; a typo or an unmounted drive used to produce an empty vault.
- **`updated_at` now means "the content changed".** It no longer moves on re-syncs,
  moves or reindexes. Dates already overwritten by earlier reindexes are not
  reconstructed; the archive candidates in `brain_report` read this column.

## Known issues

- **Notes that arrive by `git pull` get no vector until the server restarts.** The next
  hook call adds them to the keyword index, so they can be found by their words, but
  semantic search does not see them until `serve` restarts or you run `brain_sync`.
  After pulling notes from another machine, run `brain_sync`.
- **A project card's `## Archive` index grows without limit.** Every handoff rotation
  adds a line and none are removed; once the card passes 15 KB, the `brain-init` skill
  silently skips the umbrella-context step. Workaround: move older index lines into a
  separate note and link it under a heading that does not start with `Archive` —
  lines under `## Archive` that are not index entries are dropped by the next
  rotation.
- **On Windows, a note whose full path passes the 260-character limit cannot be
  read** unless long paths are enabled (`LongPathsEnabled`). Every sync reports it as
  failed: a new note never enters the index, and an indexed one keeps its old content.
  Enable long paths in Windows, or keep the vault closer to the drive root.
